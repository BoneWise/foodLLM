## 3. 本轮发现并修复的QA问题

首次全量启动v01发生在输入文件传输完成之前，因缺少prompt配置而在加载模型前退出。随后核对服务器568张图片的全部SHA-256与7,202输入清单后重新启动，保留失败日志。

全量v02在已写入171输入后，处理 `A / image23 / T` 时触发归一化检查断言：将完整序列的最后一个向量单独重新执行RMSNorm，可因浮点归约路径产生BF16舍入差异，观察到最大差0.001953125。用真实forward的norm输出重算LM head时，误差为0。

同时发现旧QA会再次触发norm hook并覆盖临时比较值，导致单独记录的`norm_error=0`不足以作为独立验证证据。实际forward生成的hidden、norm缓存及logits均在重算前取得，未被此QA替换。

修复方法：

1. 临时保留实际norm输入的原张量形状，确认其末token正是block32输出。
2. QA重算期间停用捕获hook，保留原始norm作为比较对象。
3. 要求完整形状重算norm及实际norm→LM head均精确一致；单向量重算差异仅记录作数值诊断，不用任意放宽容差掩盖错误。
4. 触发问题的输入单独重复两次通过；全部30输入重新验证通过；修复前后30个pilot缓存逐项完全一致。

科学提示、图片处理、模型精度、候选答案和读出位置均未改变。临时完整norm输入只用于QA，不保存成多token研究特征。debug版本、失败日志和脚本快照保留。
